# Sécurité

Ne publiez jamais une faille exploitable, une clé ou des données personnelles dans
un ticket public. Le canal privé de signalement GitHub doit être activé et testé par
le propriétaire avant d’être annoncé comme opérationnel. Tant que ce n’est pas confirmé,
demandez dans un ticket public **uniquement un moyen de contact privé**, sans détail technique.

Ce dépôt ne promet actuellement ni astreinte, ni délai contractuel de correction.
En cas d’exposition active : désactiver le traitement concerné, protéger l’accès,
révoquer les secrets exposés et préserver les traces utiles avec votre administrateur.

Les publications doivent relier les corrections de sécurité à une version et préciser
les mesures de migration sans exposer de données de clients.
